# Data model

The JSON snapshot is schema version 1. Collection names are intentionally short: `slots` means duty slots, `swaps` means swap requests, and `audit` means the audit log.

| Field | Purpose |
| --- | --- |
| `schemaVersion`, `revision` | Schema identifier and monotonically increasing committed snapshot revision |
| `counters` | Stable per-kind ID counters; existing IDs are never regenerated by reads |
| `users` | ID, name, email, passwordHash, role, qualification, active flag; no wholesale client serialization |
| `availability` | Nested staff ID → local YYYY-MM-DD → morning/afternoon → available/unavailable/not_submitted |
| `availabilityVersions` | Optional nested staff ID → Monday week → nonnegative optimistic version; absent legacy entry reads as 0 |
| `rosters` | ID, local Monday week, draft/published, optimistic version, creation/publication time |
| `slots` | ID, roster ID, lab-a/lab-b, local date/block, UTC startsAt/endsAt, headcount, technicianMinimum |
| `assignments` | Stable ID, slot ID, staff ID and version; swap exchanges only staff IDs |
| `swaps` | Participants, both assignment IDs and captured versions/owners, roster week, status/version, private note, timeline and decision/result |
| `notifications` | Recipient, title/message, optional swap ID, createdAt and nullable readAt |
| `audit` | Actor, action, timestamp and transition/before-after details |
| `operations` | Bounded actor/operation ID → payload hash and created swap ID for safe creation retries |
| `demo` | Optional true marker on explicitly seeded fictional data |

Every stored time representing an instant uses UTC ISO 8601 with `Z`. Monday week keys and availability dates are institution-local calendar dates. Staff availability is explicit for each date/block; a missing cell means `not_submitted`. Availability version comparison and increment happen inside the same store transaction as the save; reads do not migrate or write an old snapshot.

New passwords use explicit bcrypt with cost 12 and a 12–72 byte input policy through `Passwords`; existing hashes remain unchanged and are verified using their encoded algorithm/cost. An optional user `credentialVersion` defaults to 0 for existing users and sessions. Password reset increments it atomically; sessions with an older value are invalidated on their next authenticated request. See MIGRATION.md for long legacy bcrypt passwords and compromised archive/session handling.

Relationship: one roster has 20 slots; a slot has zero through requested headcount assignments. A technician counts once as a person and once toward the technician subset. Staff cannot have overlapping retained assignments across either lab or draft/published rosters. Every assignment belongs to active staff with explicit availability. Published coverage is validated before publication.

Swap states are `awaiting_colleague → awaiting_supervisor → approved`, with terminal `declined`, `rejected`, `withdrawn`, `expired`, or `invalidated`. Either duty beginning expires an active request. Active requests reserve both assignments inside the lock. Terminal records remain in history. Saved approval includes its before/after preview and is idempotent.

Additional private files: `state.lock` is stable across snapshot replacements; `login-throttle.json` is separate authentication bookkeeping; `sessions/` stores PHP sessions; ignored `demo-credentials*.txt` is a local setup receipt. Backups contain private data and hashes and must never be served by the web root.
