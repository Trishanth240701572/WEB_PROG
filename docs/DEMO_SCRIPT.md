# Evaluator demo (5–7 minutes)

Use the private fictional receipt in `storage/demo-credentials.txt`; never project passwords or expose that file. Pick the seeded future published week and subsequent draft. Once seeded, dates remain stable. If they are past, back up and deliberately create a fresh local demo rather than treating old duties as future. Use separate browser sessions for staff, colleague and supervisor.

1. **Availability (45 seconds).** Sign in as a staff member. Follow **My availability** to the real PHP page. Select the draft week, change free future cells, observe the available-block count/unsaved feedback and save. Reload to show persistence. Show that unavailable/unknown choices differ from available. Leave currently assigned cells available.
2. **Coverage and publication (90 seconds).** Sign in as supervisor. Open **Roster builder**, select the subsequent draft. Highlight a full-headcount slot missing a technician and another missing a person. Open the staff picker and show eligibility reasons. Replace an assistant with an available technician where needed; fill remaining gaps using eligible staff. Publish only when all 20 blocks have full people and technician coverage. The seed intentionally starts mostly empty; for a timed presentation, prepare most of the draft in advance and leave the two illustrative gaps.
3. **Candidate explanations (60 seconds).** Return to a staff session on the published week. Open **My shifts**, choose a future duty and **Request exchange**. Show an eligible candidate and blocked choices with availability, overlap or technician reasons. Submit a private note only if useful. Existing seeded pending requests reserve their assignments; use an unreserved pair or withdraw the requester's existing request first.
4. **Colleague response (45 seconds).** In the addressed colleague's session, open incoming request and accept. Reload the roster to demonstrate both owners remain unchanged. The request is now awaiting supervisor.
5. **Approval preview (60 seconds).** In supervisor **Approval inbox**, review both people's before/after assignments, coverage checks and equal scheduled hours. Approve once. Reload both staff rosters: the two assignment IDs/times/locations stay fixed while owners change. Show the approved timeline, notices and history.
6. **Reports (45 seconds).** Select the same roster week/lab in **Reports**. Compare scheduled-hour Canvas/table values, coverage and history. Change history state/staff filters, then export the corresponding CSV. Explain that exchange changes owners, not total filled places or verified worked hours.

The UI supports this workflow through real PHP persistence. The seed also provides pending colleague, pending supervisor, approved, rejected and expired examples. CLI tests use separate temporary records; do not run destructive tests against the demonstration store.
